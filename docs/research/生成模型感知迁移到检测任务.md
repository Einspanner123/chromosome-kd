# 生成模型预训练感知能力迁移到检测任务

> **目标**：将 ChromoGen 生成模型（VAE+UNet+BBox Head）训练得到的染色体域感知能力，迁移到 LDMDet 检测模型中，突破 ResNet+FPN 判别式特征的感知局限。
>
> **理论依据**：
> - 第一性原理：生成模型建模 $p(x,y|c)$，检测模型建模 $p(y|x)$；前者隐式学习数据流形的几何结构，后者仅学习判别边界。
> - He et al., "Generalized Diffusion Detector: Mining Robust Features from Diffusion Models for Domain-Generalized Detection" (CVPR 2025)
> - Zhao et al., "DICEPTION: A Generalist Diffusion Model for Visual Perceptual Tasks" (NeurIPS 2025)
> - Saini et al., "LGDM: Latent Guidance in Diffusion Models for Perceptual Evaluations" (ICML 2025)
>
> **当前代码位置**：
> - 生成模型：[projects/ChromoGen/models/chromogen_pipeline.py](../../projects/ChromoGen/models/chromogen_pipeline.py)
> - 检测模型：[ldmdet/core/head.py](../../ldmdet/core/head.py), [ldmdet/core/single_head.py](../../ldmdet/core/single_head.py)
> - 流匹配核心：[ldmdet/diffusion/rectified_flow.py](../../ldmdet/diffusion/rectified_flow.py)
> - 预训练权重：`work_dirs/chromogen_phase1/final_model.pt`（Phase 1 仅图像生成）

## 1. 问题定义与动机

### 1.1 现状

**LDMDet 检测模型**（当前 SOTA: `reproduce_0751_stochot_eps5_v2`, mAP=0.753）：
- 架构：ResNet50 + FPN + DiffusionDetHead（6 级级联）
- 检测头输入：RoI 特征（7×7×256 局部 patch）+ 时间步 embedding
- 建模范式：$p(y | x)$，$y$ 为 bbox 坐标，$x$ 为图像特征
- 局限：仅依赖 FPN 的局部感受野，缺乏对染色体整体形态、组结构、计数先验的全局感知

**ChromoGen 生成模型**（Phase 1 已训练）：
- 架构：VAE(KL-f8, frozen) + UNet(320/640/1280/1280) + Condition Encoder
- 建模范式：$p(x, y | c)$，$x$ 为图像，$y$ 为 bbox，$c$ 为类别+计数条件
- 优势：通过生成训练，VAE encoder 学到语义潜空间，UNet 学到多尺度染色体形态先验，Condition Encoder 学到类别-计数关系（核型结构知识）

### 1.2 核心假设

**假设**：能生成目标域图像的生成模型，其内部表示已包含对该域物理世界的建模感知能力。这种感知能力（形态先验、空间布局先验、计数先验）对检测任务有益，且可通过特征迁移机制被检测模型继承。

**理论支撑**：扩散模型通过学习 score function $\nabla_x \log p_t(x_t)$ 隐式编码了数据流形的几何结构。该流形上的局部切空间方向对应于数据的语义变化方向（如染色体姿态、遮挡程度），这些方向对检测任务的定位和分类同样有效。

### 1.3 核心挑战

| 挑战 | 描述 | 难度 |
|------|------|------|
| 表示空间异构 | ChromoGen 在 VAE 潜空间(4ch, H/8)操作；LDMDet 在 RGB 特征空间(256ch, H/4~H/32)操作 | 高 |
| 条件依赖不对称 | ChromoGen UNet 需要 class+count 条件 $c$；检测时仅有图像，无 $c$ | 高 |
| 时间步语义差异 | ChromoGen 用 DDPM 1000步；LDMDet 用 RF 1-6步采样 | 中 |
| 计算开销 | 多时间步特征提取增加训练/推理成本 | 中 |
| 负迁移风险 | 生成模型的纹理先验可能对检测判别无益甚至有害 | 中 |

## 2. 第一性原理分析

### 2.1 生成模型的概率建模本质

ChromoGen 训练目标是最大化数据似然的下界（ELBO）：

$$
\mathcal{L}_{\text{ELBO}} = \mathbb{E}_{q(x_0)} \left[ \mathbb{E}_{q(x_t|x_0)} \left[ \log p_\theta(x_0 | x_t, c) \right] \right] - D_{\text{KL}}\left( q(z|x_0) \| p(z) \right)
$$

其中：
- $x_0$：原始图像，$x_t$：加噪潜变量，$z$：VAE 潜变量，$c$：类别+计数条件
- $p_\theta(x_0 | x_t, c)$：UNet 参数化的去噪分布

**关键洞察**：UNet 学习的 $\epsilon_\theta(x_t, t, c) \approx -\sigma_t \nabla_{x_t} \log p_t(x_t | c)$，即 score function。该函数在每一点 $x_t$ 指向数据流形的高概率方向，编码了：

1. **形态先验**：染色体的形状、大小、姿态分布
2. **空间布局先验**：染色体的非随机排列（核型分析中的组结构）
3. **计数先验**：各类染色体的期望数量（通过 Condition Encoder 注入）

### 2.2 检测模型的判别式建模本质

LDMDet 的训练目标（简化形式）：

$$
\mathcal{L}_{\text{det}} = \mathbb{E}_{(x, y) \sim \text{data}} \left[ \mathcal{L}_{\text{cls}}(f_\phi(x, y_t), y_{\text{cls}}) + \mathcal{L}_{\text{bbox}}(f_\phi(x, y_t), y_{\text{bbox}}) \right]
$$

其中 $f_\phi$ 是检测头，$y_t$ 是加噪的 bbox 坐标。检测模型仅学习 $p(y|x)$，不建模 $p(x)$。

**关键差异**：检测模型不知道"染色体应该长什么样"，只知道"如何从背景中区分染色体"。这种判别式学习在训练数据充足时有效，但缺乏对域结构的整体理解。

### 2.3 表示学习的共性与差异

**共性**：
1. 两者都使用扩散过程（ChromoGen 用 DDPM，LDMDet 用 RF）
2. 两者都需要多尺度视觉特征（ChromoGen 用 UNet 下采样块，LDMDet 用 FPN）
3. 两者都涉及时间步条件化（ChromoGen 用 cross-attention，LDMDet 用 AdaLN-Zero）

**差异**：

| 维度 | ChromoGen | LDMDet |
|------|-----------|--------|
| 建模对象 | 图像潜空间分布 $p(z)$ | bbox 坐标分布 $p(y\|x)$ |
| 特征来源 | UNet 内部多尺度表示 | FPN + RoI 局部特征 |
| 条件信息 | class+count（显式） | 图像特征（隐式） |
| 优化方向 | 最大化似然（生成） | 最小化检测损失（判别） |
| 流形理解 | 显式建模数据流形 | 仅在判别边界附近采样 |

### 2.4 迁移的理论可行性

**定理（非正式）**：若生成模型 $p_\theta^{gen}$ 已充分拟合目标域分布 $p_{\text{data}}$，则其内部表示 $\phi^{gen}(x)$ 包含足以重建 $x$ 的语义信息，这些信息对任何依赖于 $p(y|x)$ 的下游任务（如检测）具有正迁移价值。

**论证**：
1. 由数据处理不等式，$\phi^{gen}(x)$ 关于 $x$ 的互信息 $I(\phi^{gen}(x); x) \geq I(y; x) - I(y; \phi^{gen}(x) | x)$
2. 生成模型为重建 $x$ 必须保留所有语义相关信息，包括目标位置和类别
3. 因此 $\phi^{gen}(x)$ 是检测任务的有效特征表示

**风险**：上述论证假设生成模型已充分拟合。若 ChromoGen 仅学到纹理统计而非语义结构（mode collapse），则迁移无效。需要通过探针实验验证。

## 3. 现有架构深度对比

### 3.1 ChromoGen 架构剖析

参考 [chromogen_pipeline.py:38-103](../../projects/ChromoGen/models/chromogen_pipeline.py#L38-L103)：

```
输入: pixel_values [B,3,768,768], class_labels [B,24], counts [B,24]
  │
  ├─ VAE Encoder (frozen): 768×768×3 → 96×96×4 (潜空间, ~150x压缩)
  │   └─ 强制学习语义压缩表示
  │
  ├─ Condition Encoder: class+count → [B, 25, 768] (24类token + 1 CLS token)
  │   └─ 显式编码核型结构先验
  │
  ├─ UNet (可训练):
  │   ├─ Down Block 1: 96×96×4 → 48×48×320   (H/16, 局部纹理)
  │   ├─ Down Block 2: 48×48×320 → 24×24×640 (H/32, 中尺度结构)
  │   ├─ Down Block 3: 24×24×640 → 12×12×1280 (H/64, 全局语义) + cross-attn(c)
  │   ├─ Mid Block:   12×12×1280              (bottleneck, 全局压缩) + cross-attn(c)
  │   ├─ Up Block 1:   12×12×1280 → 24×24×1280
  │   ├─ Up Block 2:   24×24×1280 → 48×48×640
  │   └─ Up Block 3:   48×48×640 → 96×96×320
  │
  └─ BBox Head (可选, Phase 2): bottleneck_feat → Transformer Decoder → bbox预测
      └─ 与检测任务的天然连接点
```

**感知能力载体**：
- **VAE Encoder**：学习到的潜空间 $z$ 中，语义相近的图像在欧氏空间中相近
- **UNet Down Blocks**：多尺度特征层次（纹理→结构→语义）
- **UNet Mid Block (bottleneck)**：1280维全局语义压缩，包含整图上下文
- **Cross-Attention 层**：将 class+count 条件注入视觉特征，建立"类别-外观"映射

### 3.2 LDMDet 架构剖析

参考 [head.py:42-117](../../ldmdet/core/head.py#L42-L117) 和 [single_head.py:42-117](../../ldmdet/core/single_head.py#L42-L117)：

```
输入: image [B,3,H,W]
  │
  ├─ ResNet50 backbone: H×W×3 → {H/4×256, H/8×512, H/16×1024, H/32×2048}
  │   └─ ImageNet预训练，对染色体域未专门优化
  │
  ├─ FPN neck: → {H/4×256, H/8×256, H/16×256, H/32×256} (4级特征金字塔)
  │   └─ 多尺度但缺乏全局上下文
  │
  ├─ DiffusionDetHead (6级级联):
  │   for each stage:
  │   ├─ RoI Extractor: 从FPN按proposal位置提取 7×7×256 局部特征
  │   ├─ SingleDiffusionDetHead:
  │   │   ├─ Self-Attention: proposals间全局交互
  │   │   ├─ DynamicConv (Instance Interaction): RoI特征与proposal交互
  │   │   ├─ FFN
  │   │   └─ AdaLN-Zero: 时间步条件化
  │   ├─ cls_head: → [N, 24] 分类logits
  │   └─ reg_head: → [N, 4] bbox增量
  │
  └─ Rectified Flow: x_t = (1-t)x_0 + t x_1, 预测x_0
```

**感知局限**：
- **局部性**：RoI 特征仅看 7×7 局部 patch，缺乏全局上下文
- **域无关**：ResNet50 在 ImageNet 上预训练，对染色体域无专门知识
- **无条件先验**：不利用 class-count 关系（尽管 CountingBranch 存在但仅用于后处理）

### 3.3 表示空间对齐分析

**空间分辨率对齐**：

| ChromoGen 层 | 分辨率 | 通道 | LDMDet 对应 |
|-------------|--------|------|------------|
| VAE 潜空间 | 96×96 (H/8) | 4 | FPN H/8 |
| UNet Down1 | 48×48 (H/16) | 320 | FPN H/16 |
| UNet Down2 | 24×24 (H/32) | 640 | FPN H/32 |
| UNet Down3 + Mid | 12×12 (H/64) | 1280 | 无对应（FPN仅到H/32） |
| UNet Up1 | 24×24 (H/32) | 1280 | FPN H/32 |
| UNet Up2 | 48×48 (H/16) | 640 | FPN H/16 |
| UNet Up3 | 96×96 (H/8) | 320 | FPN H/8 |

**关键观察**：ChromoGen 的 UNet 在 H/64 分辨率有 1280 维 bottleneck，这是 LDMDet 完全缺乏的全局语义层。这一层的特征包含整张图像的压缩表示，对检测的全局推理（如计数、组结构判断）至关重要。

## 4. 相关研究综述

### 4.1 Generalized Diffusion Detector (CVPR 2025)

**核心方法**：
1. 从扩散模型的去噪过程中提取**多时间步中间特征**
2. 融合不同时间步的特征作为 domain-invariant 表示
3. 通过**特征级对齐**（correlation-based matching）和**对象级对齐**（shared region proposals）将扩散模型能力蒸馏到轻量检测器
4. 推理时不增加计算开销

**对本项目的启发**：
- 多时间步特征提取：不同 $t$ 捕获不同粒度信息（小 $t$ 细节，大 $t$ 结构）
- 特征+对象双层对齐：既对齐特征空间，又对齐检测结果
- 蒸馏后检测器独立推理：避免推理时的生成模型开销

**差异**：该论文用通用预训练扩散模型（DDPM/DDIM），而我们有域专门的 ChromoGen（含 VAE+UNet+条件编码），表示能力更强但架构更复杂。

### 4.2 DICEPTION (NeurIPS 2025)

**核心发现**：
- 预训练在数十亿图像上的 text-to-image 扩散模型可重新用于多种感知任务
- 关键是**最大化保留预训练模型的先验知识**
- 仅需少量数据（50张图像）和参数（1%）即可适配新任务
- Classifier-free guidance 可提升感知任务性能

**对本项目的启发**：
- 保留 ChromoGen 预训练权重是关键，微调时应小学习率、少参数
- CFG 思想可用于检测：条件（class+count）vs 无条件特征的差分可增强判别力

### 4.3 LGDM (ICML 2025)

**核心方法**：
- 提出 Perceptual Manifold Guidance (PMG)
- 利用预训练 latent diffusion model 获取**多尺度、多时间步特征图**
- 证明这些 "hyperfeatures" 与人类感知高度相关
- 应用于 NR-IQA 任务

**对本项目的启发**：
- UNet 的多尺度+多时间步特征可视为 "hyperfeatures"
- 这些特征对感知任务（包括检测）具有通用价值
- 潜空间引导可保持特征在数据流形上

### 4.4 其他相关工作

- **DiffusionDet** (DiffusionDet original): 将检测建模为 bbox 坐标的扩散去噪，LDMDet 的直接前身
- **Stable Diffusion for Detection**: 多项研究探索用 SD 的 UNet 特征做检测，证明 cross-attention 特征对定位有效
- **Knowledge Distillation in Detection**: 传统检测蒸馏（FGD, FGD, MGD 等）主要在同类架构间蒸馏，跨架构（生成→判别）蒸馏是新颖方向

## 5. 迁移路径设计与理论推导

基于第一性原理分析和相关研究，提出四条迁移路径，并分析其理论依据与可行性。

### 5.1 路径 A：特征蒸馏（Feature Distillation）

#### 5.1.1 核心思想

将 ChromoGen 的多时间步中间特征作为"教师"，通过特征对齐损失指导 LDMDet 的 FPN 特征学习。

#### 5.1.2 数学推导

设 ChromoGen UNet 在时间步 $t$ 的第 $l$ 层特征为 $\phi^{CG}_{t,l}(x) \in \mathbb{R}^{C_l \times H_l \times W_l}$，LDMDet 的 FPN 第 $l$ 层特征为 $\phi^{LD}_l(x) \in \mathbb{R}^{256 \times H_l \times W_l}$。

**特征对齐损失**：

$$
\mathcal{L}_{\text{distill}} = \sum_{l} \sum_{t \in \mathcal{T}} \lambda_{l,t} \cdot \left\| \text{proj}_{l}(\phi^{LD}_l(x)) - \text{sg}(\text{norm}(\phi^{CG}_{t,l}(x))) \right\|_2^2
$$

其中：
- $\text{proj}_{l}: \mathbb{R}^{256} \to \mathbb{R}^{C_l}$：可学习的线性投影
- $\text{sg}$：stop-gradient（教师特征不参与梯度回传）
- $\text{norm}$：特征归一化（避免尺度差异）
- $\mathcal{T}$：选定的时间步集合（如 $\{0.1, 0.3, 0.5, 0.7\}$）
- $\lambda_{l,t}$：层-时间步权重

**Correlation-based Matching**（参考 CVPR 2025 GDD）：

更鲁棒的对齐方式是最大化特征通道间的相关性：

$$
\mathcal{L}_{\text{corr}} = -\sum_{l} \sum_{t} \text{tr}\left( \frac{C_{l,t}^\top C_{l,t}}{\|C_{l,t}\|_F^2} \right)
$$

其中 $C_{l,t} = \text{corr}(\text{proj}_l(\phi^{LD}_l), \phi^{CG}_{t,l})$ 是通道相关矩阵。这种方式不要求特征数值匹配，只要求相关性结构匹配，对域差异更鲁棒。

#### 5.1.3 条件问题与解决方案

**问题**：ChromoGen UNet 的前向需要条件 $c = (\text{class\_labels}, \text{counts})$，检测时仅有图像。

**方案**：
- **训练时**：使用 GT 的 class+count 作为 teacher forcing（参考 [chromogen_pipeline.py:124-130](../../projects/ChromoGen/models/chromogen_pipeline.py#L124-L130) 的 condition 编码）
- **推理时**：用 LDMDet 的 CountingBranch 预测 count，用上一轮检测结果的 class 分布作为条件
- **退化为无条件**：参考 CFG 思想，使用空条件 + 预测条件的加权组合

#### 5.1.4 优劣分析

**优势**：
- 架构改动小：仅增加投影层和蒸馏损失
- 训练稳定：教师特征是固定的
- 推理无额外开销：蒸馏后 LDMDet 独立推理

**劣势**：
- 教师能力上限受投影层限制
- 无法利用 ChromoGen 的动态去噪过程（仅用静态特征）
- 条件依赖问题需要额外处理

### 5.2 路径 B：分数引导采样（Score-Guided Sampling）

#### 5.2.1 核心思想

在 LDMDet 的 bbox 扩散采样过程中，用 ChromoGen 的图像分数函数提供先验引导，类似 classifier guidance。

#### 5.2.2 数学推导

LDMDet 的 bbox 扩散 ODE：

$$
\frac{dx_\tau}{d\tau} = v_\theta^{LD}(x_\tau, \tau, \phi^{LD}(x))
$$

其中 $x_\tau$ 是 bbox 坐标，$\phi^{LD}(x)$ 是图像特征。

**引导思路**：ChromoGen 的图像分数 $\nabla_{x_t} \log p_t^{CG}(x_t | c)$ 提供了"图像应该长什么样"的先验。虽然它不在 bbox 空间，但可以通过特征梯度间接引导：

$$
\tilde{v}_\theta = v_\theta^{LD} + \lambda \cdot \nabla_{x_\tau} \langle \phi^{LD}(x), \text{sg}(\phi^{CG}_{t^*}(x_t)) \rangle
$$

其中 $\phi^{CG}_{t^*}(x_t)$ 是 ChromoGen 在某时间步 $t^*$ 的特征，$\langle \cdot, \cdot \rangle$ 是特征相似度。直观上：当 bbox 移动方向使 LDMDet 特征更接近 ChromoGen 特征时，给予奖励。

#### 5.2.3 实现挑战

**主要问题**：ChromoGen 在 VAE 潜空间操作，$\phi^{CG}$ 的梯度无法直接回传到 RGB 图像。需要通过 VAE decoder 的 Jacobian 链式回传，计算成本高。

**替代方案**：用 ChromoGen 的特征作为 LDMDet 特征的"正则化目标"，而非直接引导采样轨迹。这退化为路径 A 的特征蒸馏。

#### 5.2.4 优劣分析

**优势**：
- 理论优雅：直接利用生成模型的 score function
- 推理时可调：通过 $\lambda$ 控制引导强度

**劣势**：
- 计算复杂：需要跨空间梯度回传
- 实现难度高：VAE decoder Jacobian 计算不稳定
- 收益不确定：bbox 空间和图像空间的引导关系不直接

### 5.3 路径 C：潜空间桥接（Latent Space Bridging）

#### 5.3.1 核心思想

将 ChromoGen 的 VAE+UNet 作为额外的"特征提取器"，通过桥接模块将其输出投影到 LDMDet 的特征空间，与 FPN 特征融合。

#### 5.3.2 架构设计

```
Real Image [B,3,768,768]
    │
    ├──────────────────────────┐
    │                          │
    ▼                          ▼
ResNet50+FPN              ChromoGen VAE Encoder (frozen)
    │                          │
    │                          ▼
    │                  Latent z [B,4,96,96]
    │                          │
    │                  ChromoGen UNet (frozen, t=t*)
    │                          │
    │              ┌───────────┼───────────┐
    │              ▼           ▼           ▼
    │          Down1 feat  Down2 feat  Bottleneck feat
    │          [320,H/16]  [640,H/32]  [1280,H/64]
    │              │           │           │
    │              ▼           ▼           ▼
    │          Bridge Module (可学习投影+上采样)
    │              │           │           │
    │              ▼           ▼           ▼
    │          [256,H/16]  [256,H/32]  [256,H/64]
    │              │           │           │
    ▼              │           │           │
FPN feats         │           │           │
[H/4~H/32]        │           │           │
    │              │           │           │
    └──────────────┴───────────┴───────────┘
                   │
                   ▼
            Fused FPN feats (增强)
                   │
                   ▼
            LDMDet Head (不变)
```

#### 5.3.3 数学推导

设 FPN 特征为 $\{F^{LD}_i\}_{i=1}^{4}$，ChromoGen 特征为 $\{F^{CG}_j\}_{j=1}^{3}$（Down1, Down2, Bottleneck）。

**桥接模块**：

$$
\hat{F}^{CG}_j = \text{Upsample}_{j \to i}\left( \text{Conv}_{1\times1}^{C_j \to 256}(F^{CG}_j) \right)
$$

**特征融合**（参考 FPN 的 lateral connection）：

$$
F^{fused}_i = F^{LD}_i + \alpha_i \cdot \hat{F}^{CG}_{j(i)} + \beta_i \cdot \text{Conv}_{3\times3}(F^{LD}_i + \hat{F}^{CG}_{j(i)})
$$

其中 $\alpha_i, \beta_i$ 是可学习的融合权重（初始化为 0，保证训练初始不破坏 baseline）。

#### 5.3.4 条件处理

**训练时**：用 GT class+count 编码条件 $c$，注入 UNet 的 cross-attention。

**推理时**：三种策略：
1. **无条件推理**：$c = \text{zeros}$，依赖 UNet 已学到的无条件先验
2. **自举推理**：先用无条件 LDMDet 检测，用检测结果估计 class+count，再用条件 ChromoGen 重新提取特征
3. **CountingBranch 预测**：用 LDMDet 的 CountingBranch 预测 count，class 用先验分布

#### 5.3.5 优劣分析

**优势**：
- 架构清晰：ChromoGen 作为特征提取器，与 LDMDet 解耦
- 信息丰富：利用 ChromoGen 的多尺度+全局 bottleneck 特征
- 可解释：可可视化 ChromoGen 特征对检测的贡献

**劣势**：
- 推理开销大：需要 VAE encode + UNet forward
- 条件依赖：推理时的条件处理引入误差
- 域差异：ChromoGen 训练时见的是 VAE 重建图像，检测时是真实图像（虽然 VAE encode 真实图像是可行的）

### 5.4 路径 D：条件生成作为检测先验（Conditional Generation as Detection Prior）

#### 5.4.1 核心思想

利用 ChromoGen 的 BBox Head（Phase 2 联合训练后）作为"先验检测器"，生成初始 bbox proposals，LDMDet 作为"精炼器"优化这些 proposals。

#### 5.4.2 两阶段流程

**Stage 1: ChromoGen 先验生成**

$$
y_{\text{init}} \sim p^{CG}_{\text{bbox}}(y | c, \phi^{CG}(x))
$$

ChromoGen 的 BBox Head（参考 [bbox_head.py](../../projects/ChromoGen/models/bbox_head.py)）基于 UNet bottleneck 特征和条件 $c$，通过 Rectified Flow 生成 bbox 坐标。

**Stage 2: LDMDet 精炼**

$$
y_{\text{final}} = \text{LDMDet}_{\text{refine}}(x, y_{\text{init}})
$$

LDMDet 不从纯噪声开始，而是从 $y_{\text{init}}$ 开始，用少量步数精炼。

#### 5.4.3 数学推导

将 LDMDet 的初始噪声 $x_1 \sim \mathcal{N}(0, I)$ 替换为 ChromoGen 输出的加噪版本：

$$
x_1^{\text{init}} = (1 - t_{\text{init}}) \cdot y_{\text{init}}^{\text{scaled}} + t_{\text{init}} \cdot \epsilon, \quad \epsilon \sim \mathcal{N}(0, I)
$$

从 $t = t_{\text{init}}$（而非 $t=1$）开始 RF 采样，减少所需的去噪步数。

**优势**：ChromoGen 的先验使 LDMDet 从更好的起点开始优化，理论上可用更少步数达到更高精度。

#### 5.4.4 优劣分析

**优势**：
- 利用 ChromoGen 的 BBox 生成能力（已验证的 Phase 2 功能）
- 减少 LDMDet 采样步数
- 天然融合 class+count 先验

**劣势**：
- 依赖 ChromoGen Phase 2 训练（目前仅 Phase 1 完成）
- 两阶段推理增加延迟
- 误差累积：ChromoGen 的错误先验可能误导 LDMDet

### 5.5 混合路径推荐

综合分析，推荐**路径 C + 路径 A 的混合方案**，分阶段实施：

**核心理由**：
1. 路径 C 提供最丰富的特征信息（多尺度+全局 bottleneck）
2. 路径 A 的蒸馏思想可在路径 C 基础上进一步对齐特征空间
3. 两者都避免了路径 B 的复杂梯度计算和路径 D 的 Phase 2 依赖

**具体方案**：
- **短期（Phase 1-2）**：路径 C（特征桥接），利用 ChromoGen Phase 1 权重
- **中期（Phase 3）**：加入路径 A（特征蒸馏），将 ChromoGen 特征"内化"到 LDMDet
- **长期（Phase 4）**：路径 D（先验生成），待 ChromoGen Phase 2 完成后探索

## 6. 架构改动方案

### 6.1 Feature Bridge Module (FBM)

**目标**：将 ChromoGen 的多尺度特征投影并融合到 LDMDet 的 FPN 特征中。

**新增模块**（基于路径 C）：

```python
class FeatureBridgeModule(nn.Module):
    """将 ChromoGen 特征桥接到 LDMDet FPN 特征空间

    ChromoGen 特征来源:
      - UNet Down1: [B, 320, H/16, W/16]  → 对齐 FPN level 2 (H/16)
      - UNet Down2: [B, 640, H/32, W/32]  → 对齐 FPN level 3 (H/32)
      - UNet Mid:   [B, 1280, H/64, W/64] → 新增 level 5 (H/64, 全局语义)

    FPN 原有特征:
      - Level 0: [B, 256, H/4, W/4]    (无 ChromoGen 对应)
      - Level 1: [B, 256, H/8, W/8]    (无 ChromoGen 对应, 但可从Up3获取)
      - Level 2: [B, 256, H/16, W/16]
      - Level 3: [B, 256, H/32, W/32]
    """

    def __init__(self, cg_channels=[320, 640, 1280], ld_channels=256):
        super().__init__()
        # 投影层: ChromoGen 通道 → LDMDet 通道
        self.proj_down1 = nn.Conv2d(cg_channels[0], ld_channels, 1)
        self.proj_down2 = nn.Conv2d(cg_channels[1], ld_channels, 1)
        self.proj_mid = nn.Conv2d(cg_channels[2], ld_channels, 1)

        # 可学习融合权重 (零初始化, 保证训练初始不破坏 baseline)
        self.alpha = nn.Parameter(torch.zeros(3))

        # 全局特征注入: bottleneck → 1x1 conv → 广播
        self.global_proj = nn.Sequential(
            nn.AdaptiveAvgPool2d(1),
            nn.Flatten(),
            nn.Linear(cg_channels[2], ld_channels),
            nn.GELU(),
            nn.Linear(ld_channels, ld_channels),
        )

    def forward(self, ld_feats, cg_feats):
        """
        Args:
            ld_feats: list of 4 FPN features [B,256,H/4~H/32]
            cg_feats: dict with 'down1', 'down2', 'mid' from ChromoGen UNet
        Returns:
            fused_feats: list of 4 enhanced FPN features
        """
        fused = list(ld_feats)  # copy

        # 层级对齐融合
        # Level 2 (H/16) ← CG Down1
        cg_d1 = self.proj_down1(cg_feats['down1'])
        fused[1] = fused[1] + self.alpha[0] * cg_d1  # FPN level1 = H/8, 需对齐
        # 注意: 需根据实际分辨率对齐, 此处简化

        # Level 3 (H/32) ← CG Down2
        cg_d2 = self.proj_down2(cg_feats['down2'])
        fused[2] = fused[2] + self.alpha[1] * cg_d2

        # 全局语义注入: bottleneck → 所有层级
        global_feat = self.global_proj(cg_feats['mid'])  # [B, 256]
        global_feat = global_feat.unsqueeze(-1).unsqueeze(-1)  # [B, 256, 1, 1]
        for i in range(len(fused)):
            fused[i] = fused[i] + self.alpha[2] * global_feat

        return fused
```

### 6.2 条件适配模块

**问题**：ChromoGen UNet 需要 class+count 条件，检测时未知。

**方案**：CountingBranch 已存在于 LDMDet（参考 [head.py:225-235](../../ldmdet/core/head.py#L225-L235)），可复用其输出作为条件。

```python
class ConditionAdapter(nn.Module):
    """将 LDMDet 的 CountingBranch 输出适配为 ChromoGen 条件格式

    ChromoGen 条件: [B, 25, 768] (24类token + CLS token)
    LDMDet CountingBranch: 预测总计数 (标量或类别计数)
    """

    def __init__(self, num_classes=24, embed_dim=768):
        super().__init__()
        self.num_classes = num_classes
        # 从计数预测生成伪 class_labels (均匀分布)
        self.class_embed = nn.Embedding(num_classes, embed_dim)
        # 计数编码 (复用 ChromoGen 的 SinusoidalCountEncoding 思路)
        self.count_proj = nn.Sequential(
            nn.Linear(1, embed_dim),
            nn.GELU(),
            nn.Linear(embed_dim, embed_dim),
        )
        self.cls_token = nn.Parameter(torch.randn(1, 1, embed_dim) * 0.02)
        self.norm = nn.LayerNorm(embed_dim)

    def forward(self, pred_count, class_prior=None):
        """
        Args:
            pred_count: [B] 预测的总计数
            class_prior: [B, 24] 类别先验分布 (可选, 来自上一轮检测)
        Returns:
            condition: [B, 25, 768] 适配后的条件
        """
        B = pred_count.shape[0]
        device = pred_count.device

        # 类别 embedding: 用先验或均匀分布
        if class_prior is None:
            class_labels = torch.arange(self.num_classes, device=device).unsqueeze(0).expand(B, -1)
        else:
            class_labels = torch.arange(self.num_classes, device=device).unsqueeze(0).expand(B, -1)

        cls_emb = self.class_embed(class_labels)  # [B, 24, 768]

        # 计数编码: 将总计数广播到各类 (简化, 实际可用更精细的分配)
        count_per_class = pred_count.float().unsqueeze(-1) / self.num_classes  # [B, 1]
        count_enc = self.count_proj(count_per_class.unsqueeze(1).expand(-1, self.num_classes, -1))

        tokens = cls_emb + count_enc  # [B, 24, 768]
        cls_tokens = self.cls_token.expand(B, -1, -1)  # [B, 1, 768]
        tokens = torch.cat([cls_tokens, tokens], dim=1)  # [B, 25, 768]
        return self.norm(tokens)
```

### 6.3 多时间步特征聚合

参考 CVPR 2025 GDD，提取多个时间步的 ChromoGen 特征并聚合：

```python
class MultiTimestepAggregator(nn.Module):
    """多时间步特征聚合

    不同时间步捕获不同粒度:
      - t=0.1: 接近原图, 捕获细节
      - t=0.3: 中等噪声, 捕获局部结构
      - t=0.5: 半噪半信号, 捕获全局结构
      - t=0.7: 高噪声, 捕获语义概念
    """

    def __init__(self, channels=1280, num_timesteps=4):
        super().__init__()
        self.timesteps = [0.1, 0.3, 0.5, 0.7][:num_timesteps]
        # 可学习时间步权重
        self.t_weights = nn.Parameter(torch.ones(num_timesteps) / num_timesteps)

    def forward(self, feats_per_t):
        """
        Args:
            feats_per_t: list of features, each [B, C, H, W], 对应不同 t
        Returns:
            aggregated: [B, C, H, W]
        """
        weights = F.softmax(self.t_weights, dim=0)
        aggregated = sum(w * f for w, f in zip(weights, feats_per_t))
        return aggregated
```

## 7. 实验设计与验证路径

### 7.1 Phase 0: 感知能力探针实验（验证假设）

**目标**：量化验证 ChromoGen 特征确实包含对检测有用的信息，决定是否值得迁移。

**实验设计**：
1. **Linear Probe**：在 ChromoGen 的冻结特征（VAE latent, UNet down/mid/up 特征）上训练线性分类器，预测 bbox 坐标和类别
2. **CKA 分析**：计算 ChromoGen 特征与 LDMDet FPN 特征的 Centered Kernel Alignment，衡量表示相似度
3. **特征可视化**：t-SNE 可视化 ChromoGen 特征空间中不同类别/尺度的聚类情况

**预期结果**：
- ChromoGen bottleneck 特征的 linear probe mAP > 0.3（证明有检测信息）
- CKA < 0.5（证明特征空间正交，有迁移价值）
- t-SNE 显示类别可分聚类

**风险**：若 linear probe mAP < 0.1，说明 ChromoGen 仅学到纹理统计，迁移无意义，需停止。

### 7.2 Phase 1: 冻结特征注入（最小架构改动）

**目标**：用路径 C（特征桥接）验证 ChromoGen 特征对 LDMDet 的增益。

**配置**：
- ChromoGen 完全冻结（VAE + UNet + Condition Encoder）
- 仅训练 FBM + LDMDet
- 使用 GT class+count 作为 ChromoGen 条件（teacher forcing）
- 单时间步 $t=0.5$（简化）

**消融实验**：

| 实验编号 | ChromoGen 特征 | 时间步 | 融合方式 | 条件 |
|---------|---------------|--------|---------|------|
| P1-A | 仅 bottleneck (mid) | t=0.5 | 加法 | GT |
| P1-B | down1+down2+mid | t=0.5 | 加法 | GT |
| P1-C | down1+down2+mid | t=0.5 | FBM | GT |
| P1-D | down1+down2+mid | 多时间步 | FBM | GT |
| P1-E | down1+down2+mid | 多时间步 | FBM | 无条件 |

**成功标准**：mAP 提升 ≥ 1.0%（相对 baseline 0.753）

### 7.3 Phase 2: 联合微调（中等架构改动）

**目标**：解冻 ChromoGen 部分层，端到端优化。

**配置**：
- 解冻 UNet 的 up blocks（保留 down + mid 冻结，保护预训练知识）
- 联合训练 FBM + LDMDet + UNet up blocks
- 小学习率（1e-5）微调 UNet，避免灾难性遗忘

**消融实验**：

| 实验编号 | 解冻范围 | 学习率 | 蒸馏损失 | 条件处理 |
|---------|---------|--------|---------|---------|
| P2-A | 无（=Phase 1） | - | 无 | GT |
| P2-B | Up blocks | 1e-5 | 无 | GT |
| P2-C | Up blocks | 1e-5 | 特征蒸馏 | GT |
| P2-D | Up blocks | 1e-5 | 特征蒸馏 | CountingBranch预测 |
| P2-E | 全UNet | 1e-6 | 特征蒸馏 | CountingBranch预测 |

**风险**：解冻后 mAP 下降，说明微调破坏预训练知识（参考 DICEPTION 的发现：保留预训练先验是关键）。

### 7.4 Phase 3: 分数引导采样（推理时迁移）

**目标**：在推理时用 ChromoGen 的特征引导 LDMDet 的 bbox 扩散采样，无需训练。

**配置**：
- LDMDet 训练不变（用 Phase 1/2 的模型）
- 推理时：每个采样步，计算 LDMDet 特征与 ChromoGen 特征的相似度，调整采样方向

**实验**：

| 实验编号 | 引导方式 | 引导强度 λ | 时间步 |
|---------|---------|-----------|--------|
| P3-A | 特征点积 | 0.1 | 全步 |
| P3-B | 特征点积 | 0.5 | 仅前2步 |
| P3-C | 特征余弦 | 0.3 | 全步 |

**成功标准**：mAP 提升 ≥ 0.5%，且不增加训练成本

### 7.5 Phase 4: 全集成（大架构改动）

**目标**：基于 ChromoGen 架构重新设计检测模型，共享 VAE+UNet 主干。

**配置**：
- Backbone 替换：ResNet50 → ChromoGen VAE Encoder + UNet (作为特征提取器)
- Neck 替换：FPN → 从 UNet 多尺度特征提取
- Head 不变：DiffusionDetHead
- 联合训练：检测损失 + 生成损失（多任务）

**这是最大改动，需在 Phase 1-3 验证可行后再进行。**

## 8. 理论验证与风险分析

### 8.1 信息论验证

**验证问题**：ChromoGen 特征 $\phi^{CG}(x)$ 包含多少检测相关信息？

**度量**：互信息 $I(\phi^{CG}(x); y)$，其中 $y$ 是 GT bbox+label。

**估算方法**：
- InfoNCE 估计：用对比学习框架估计互信息下界
- 若 $I(\phi^{CG}(x); y) > I(\phi^{LD}(x); y) - \delta$，则迁移有价值

### 8.2 流形对齐验证

**验证问题**：ChromoGen 特征空间与 LDMDet 特征空间是否对齐？

**度量**：CKA (Centered Kernel Alignment)

$$
\text{CKA}(X, Y) = \frac{\|X^\top Y\|_F^2}{\|X^\top X\|_F \cdot \|Y^\top Y\|_F}
$$

**预期**：
- 迁移前 CKA 较低（< 0.3），表示空间正交
- 迁移后 CKA 适中（0.4-0.6），表示部分对齐但保留互补信息
- CKA 过高（> 0.8）表示特征冗余，无迁移价值

### 8.3 风险分析

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| ChromoGen 特征对检测无益 | 中 | 高 | Phase 0 探针实验先行验证 |
| 条件依赖导致推理退化 | 中 | 中 | CountingBranch 自适应条件 + 无条件回退 |
| 计算开销过大 | 高 | 中 | 多时间步 → 单时间步；特征缓存 |
| 灾难性遗忘 | 中 | 高 | 小学习率；渐进式解冻；EMA |
| 负迁移（纹理先验干扰判别） | 低 | 高 | 分层消融；可学习融合权重（零初始化） |

### 8.4 与现有 5 个突破方向的关系

| 现有方向 | 与本方案关系 |
|---------|------------|
| 方向一：非平衡 OT 耦合 | 正交：改进 LDMDet 内部耦合，不涉及特征来源 |
| 方向二：计数先验约束 | 协同：CountingBranch 可为 ChromoGen 条件提供 count |
| 方向三：SNR 感知匹配 | 正交：改进 criterion，与特征迁移独立 |
| 方向四：非线性轨迹 | 正交：改进 RF 采样，与特征来源独立 |
| 方向五：组条件化分层 | 协同：组结构先验可来自 ChromoGen 的 condition encoding |

**本方案与现有方向正交，可叠加使用。**

## 9. 思考日志

### 2026-06-25: 初始分析

**思考 1: 为什么生成模型的感知能力对检测有用？**

从第一性原理看，检测模型 $p(y|x)$ 和生成模型 $p(x,y|c)$ 都需要理解图像内容，但角度不同：
- 检测模型仅需在特征空间中找到判别边界
- 生成模型需要理解数据的完整分布，包括"什么是正常的染色体图像"

生成模型的额外知识包括：
1. 染色体的典型形态（着丝粒位置、长短臂比例）
2. 染色体间的空间关系（核型分析中的组结构）
3. 类别-计数关系（B组2个，C组7个等）

这些知识通过显式条件（class+count）和隐式先验（UNet 学到的分布）编码在 ChromoGen 中。

**思考 2: 为什么选择路径 C（特征桥接）作为首选？**

四条路径的权衡：
- 路径 A（蒸馏）：最简单但能力上限受投影层限制
- 路径 B（分数引导）：理论优雅但实现复杂，跨空间梯度不稳定
- 路径 C（桥接）：架构清晰，信息丰富，推理开销可控
- 路径 D（先验生成）：依赖 Phase 2，且两阶段推理延迟高

路径 C 的核心优势：直接利用 ChromoGen 的多尺度特征，特别是 1280 维 bottleneck（H/64），这是 LDMDet 完全缺乏的全局语义层。通过零初始化的融合权重，保证训练初始不破坏 baseline，渐进式引入生成先验。

**思考 3: 条件依赖问题如何解决？**

这是最大的工程挑战。ChromoGen UNet 的 cross-attention 需要 class+count 条件，但检测时仅有图像。

三层解决方案：
1. **训练时**：用 GT class+count（teacher forcing），让 FBM 学会利用条件化的 ChromoGen 特征
2. **推理时**：用 LDMDet 的 CountingBranch 预测 count，class 用先验分布或上一轮检测
3. **退化方案**：若条件预测不准，用空条件（unconditional）+ ChromoGen 的无条件先验

参考 DICEPTION 的发现：即使无条件，预训练扩散模型的特征仍保留大部分感知能力。条件是"增强"而非"必需"。

**思考 4: 多时间步特征的物理意义**

不同时间步的 ChromoGen UNet 特征捕获不同粒度：
- $t \approx 0$：特征 ≈ 原图特征，细节丰富但缺乏抽象
- $t \approx 0.5$：特征保留主要结构，去除细节噪声
- $t \approx 1$：特征 ≈ 纯语义概念，无空间细节

对检测任务，中等时间步（$t \in [0.3, 0.7]$）可能最有价值：既有足够的结构信息，又避免了纯噪声的无意义。这需要消融实验验证。

**思考 5: 与 CVPR 2025 GDD 的关键差异**

GDD 用通用预训练扩散模型（如 DDPM 在 ImageNet 上的），目标是 domain generalization。我们的场景：
1. ChromoGen 是域专门的（染色体图像），不是通用的
2. 我们的目标是 in-domain 性能提升，不是 domain generalization
3. ChromoGen 有显式的 class+count 条件编码，GDD 没有

这意味着：
- 我们的特征可能更强（域专门），但也可能更窄（过拟合到生成任务）
- 我们可以利用条件信息做 conditional feature extraction，GDD 不能
- 但我们需要解决条件依赖问题，GDD 不需要

**思考 6: 实施优先级建议**

基于风险-收益分析，建议优先级：
1. **Phase 0 探针实验**（必须）：验证 ChromoGen 特征是否有检测信息，1-2 天可完成
2. **Phase 1 冻结特征注入**（高优先级）：最小架构改动，验证迁移有效性
3. **Phase 2 联合微调**（中优先级）：在 Phase 1 成功后进行
4. **Phase 3 分数引导**（低优先级）：仅训练后推理时改进，收益有限
5. **Phase 4 全集成**（远期）：大改动，需充分验证后进行
