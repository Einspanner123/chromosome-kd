## 1. 理论推导脉络整理

论文的理论推导可分为三层，每层有不同的可证伪性强度：

### 1.1 诊断层（机制识别，已部分证实）

> **统计严谨性声明**: 以下标签均基于**单种子**实验结果。0.001-0.004 mAP 量级的差异在 CV 训练噪声内（典型 run-to-run 方差 0.3-0.8%），不足以做因果归因。"方向一致"表示实验趋势与理论预言相同；"未复现"表示在 E4.3 架构下未观察到论文预言的方向，但并非"推翻"。

```
现象: Hard OT mAP 0.735 << Random 0.751  (C1, 完全证实, Δ=0.016)
   │
   ├─→ 机制一: 多样性崩溃  (C2, 完全证实)
   │     H(V|Z): 3.841 → 0.000
   │     理论: 确定性 OT 使 p(j|z) 为独热, H→0
   │
   └─→ 机制二: CAM 定理   (C3, 方向一致但存在轻微反驳)
         argmax D_eff ≈ 2.80 (ε-不变)
         sample D_eff: 2.81 → 5.31 (ε-递增)
         理论: argmax 是非连续算子, ∂π_argmax/∂ε = 0 a.e.
         ⚠️ E4.3: ε=1→2→3 mAP=0.752→0.752→0.750, ε=3 下降 0.002 (轻微反驳)
```

**诊断层的可证伪命题**:
- P1.1: `H(V|Z)_{HardOT} = 0` 且 `H(V|Z)_{Random} = log M`
- P1.2: `D_eff(argmax, ε) ≈ const` 跨 ε ∈ [0.01, 100]
- P1.3: `D_eff(sample, ε)` 单调递增
- P1.4: 组间方差崩溃比例 > 组内方差崩溃比例

### 1.2 方法层（修复方案，存在矛盾）

```
诊断 → 修复: Sinkhorn 采样替代 argmax  (C4, 方向相反但未达统计显著)
   │
   ├─→ 理论: sample 保留 ε-多样性控制
   │     E[π_stoch] = P_ε, H(π_stoch(i)|x_1) = H(P_ε[i,:]) 严格单调
   │
   ├─→ 论文证据: sample(ε=5)=0.750 > argmax(ε=5)=0.744  (+0.006, 单种子)
   │
   └─→ E4.3 反转: argmax(ε=1)=0.752 > multinomial(ε=1)=0.748  (-0.004)
         ↑ Δ=0.004 在单种子噪声内，5 个混淆变量
         ↑ 不能"推翻"论文主张，仅表明 E4.3 架构下未复现
         ↑ 矛盾根源待查 (V1 实验组)
```

**方法层的可证伪命题**:
- P2.1: `mAP(sample, ε) > mAP(argmax, ε)` 对所有 ε 成立 — **E4.3 下方向相反但未达统计显著（未复现，非推翻）**
- P2.2: `mAP(sample, ε)` 在 ε ≈ 5 达峰（三区域结构）
- P2.3: GHSS > 全局 Sinkhorn sample（领域结构增益）
- P2.4: 双随机性必要（Sinkhorn > 温度缩放）

### 1.3 原则层（普适性主张，需修正）

```
方法 → 原则: "多样性优于传输效率"  (C10, 需修正)
   │
   ├─→ 强主张: 多样性是首要优化目标（普适）
   │     问题: E4.3 argmax(低多样性) ≈ sample(高多样性)
   │
   └─→ 修正主张: 多样性是必要条件（阈值效应, 待验证假说）
         D_eff < 2: 性能急剧下降
         D_eff ∈ [2, 5]: 性能饱和
         D_eff > 5: 无额外收益
         ⚠️ 当前证据不足: 仅 3 个数据点 + 5 个混淆变量
```

**原则层的可证伪命题**:
- P3.1: 存在多样性阈值 D*，使 `mAP(D < D*)` 急剧下降，`mAP(D ≥ D*)` 饱和（**待验证假说**，非结论）
- P3.2: 多样性饱和后，`mAP` 与 `D_eff` 无关（架构上限主导）
- P3.3: 0.752 是架构上限 — **部分推翻**（训练上限 0.752-0.753 未被推翻；硬上限被 DPM++ 0.755 推翻，但来自推理端改进而非训练）

## 5. 实验方案设计

### 5.1 实验 V1: C4 矛盾根源调查（统一架构对照）

**目标**: 在统一架构下，隔离 `解码策略 × ε × OT 实现` 三个因素，查明 sample vs argmax 反转的根源。

**假设**: 论文的 "sample > argmax" 结论依赖于 (legacy OTCoupling + 行归一化 + ε=5 + 20 迭代)；E4.3 的反转依赖于 (OTFlowCoupling + 列归一化 + ε=1 + 10 迭代)。

**实验矩阵** (3×3×2 = 18 组，但实际只需关键对照):

| 实验组 | 类型 | OT 实现 | 归一化 | 解码 | ε | 迭代 | 预期 |
|:------:|:----:|:-------:|:------:|:----:|:-:|:----:|:----:|
| V1-A | 复现验证 | legacy | 行 | sample | 5 | 20 | ≈ 0.750 (论文表1) |
| V1-B | 复现验证 | legacy | 行 | argmax | 5 | 20 | ≈ 0.744 (论文表1) |
| V1-C | 复现验证 | new | 列 | sample | 1 | 10 | ≈ 0.748 (E4.3 multinomial) |
| V1-D | 复现验证 | new | 列 | argmax | 1 | 10 | ≈ 0.752 (E4.3 eps1) |
| **V1-E** | **新对照** | **new** | **列** | **sample** | **5** | **20** | **关键对照** |
| **V1-F** | **新对照** | **new** | **列** | **argmax** | **5** | **20** | **关键对照** |
| **V1-G** | **新对照** | **legacy** | **行** | **sample** | **1** | **10** | **关键对照** |
| **V1-H** | **新对照** | **legacy** | **行** | **argmax** | **1** | **10** | **关键对照** |

**实验组类型说明**:
- **复现验证组 (V1-A/B/C/D)**: 在原论文/E4.3 架构下重复实验，验证单种子结果的可复现性。若复现失败，需检查配置细节差异。
- **新对照组 (V1-E/F/G/H)**: 交叉组合架构变量，隔离 ε 和 OT 实现的影响。**这些组是修正论文 C4 主张的关键证据来源，必须做 3 种子（见 §9.3）**。

**关键对照**:
- V1-E vs V1-F: 在新版 OT + ε=5 + 20 迭代下，sample vs argmax
- V1-G vs V1-H: 在 legacy OT + ε=1 + 10 迭代下，sample vs argmax
- 若 V1-E > V1-F 且 V1-G < V1-H，则"反转"源于 ε 而非 OT 实现

**统一架构**: ResNet50 + FPN + 6×AdaLN-Zero SingleHead + Heun + Shifted(s=3) + bs=2 + 150ep

**预期成果**: 确定 "sample > argmax" 的**边界条件**，修正论文 C4 主张。

**配置文件**: `experiments/configs/ldmdet/verify_v1_{A-H}.py` (8 个配置)

### 5.2 实验 V2: 传输矩阵几何特性测量（离线）

**目标**: **仅测量传输矩阵本身的几何特性**——H(V|Z)、D_eff、ρ、η 随 ε 的变化。不涉及训练，不与 V3 联合分析。

**重要定位声明**:
> V2 是从 SOTA checkpoint (ε=5 训练得到) 出发的**离线测量**，反映的是"在 ε=5 训练的模型下，不同 ε 传输矩阵的几何特性"。
> V3 是**重新训练**不同 ε 的模型，反映的是"不同 ε 训练后的 mAP"。
> **两者样本来源不同**（V2 是 ε=5 训练的模型；V3 是各 ε 训练的模型），**不能直接做 (D_eff, mAP) 联合回归**。
> V2 验证的是 P1.1-P1.3（传输矩阵几何特性）；V3 验证的是 P2.2（ε-mAP 关系）。两者的 D_eff 数据不可混用。

**离线部分 (V2)**: 不需训练，从 SOTA checkpoint 加载，对验证集计算:
- 不同 ε 下的传输矩阵 P_ε
- H(V|Z; ε), D_eff(ε), ρ(ε), η(ε)
- 输出: `diversity_phase_diagram.json`

**验证命题**（仅限传输矩阵几何特性）:
- P1.1: `H(V|Z)_{HardOT} = 0` 且 `H(V|Z)_{Random} = log M`
- P1.2: `D_eff(argmax, ε) ≈ const` 跨 ε
- P1.3: `D_eff(sample, ε)` 单调递增

### 5.2b 实验 V3: ε-mAP 完整扫描（在线训练）

**目标**: 在统一架构 (legacy OT + 行归一化 + sample 解码) 下，训练 10 个 ε 值，绘制 ε-mAP 相图。

**训练矩阵**: ε ∈ {0.01, 0.1, 0.5, 1, 2, 3, 5, 10, 50, 100}
- 每个 ε 训练 150 ep，记录 best mAP
- 输出: `epsilon_scan.json` (ε, mAP, AP50, AP75, APs, APm, APl)

**预期成果**:
- 验证 P2.2 (三区域结构): mAP 是否在 ε ≈ 5 达峰？

### 5.3 实验 V4: 多样性阈值效应验证

**目标**: 验证"多样性阈值"假说——存在 D*，使 D_eff < D* 时 mAP 急剧下降，D_eff ≥ D* 时 mAP 饱和。

**方法**: 收集 V3 的 (D_eff, mAP) 数据点，拟合两段模型:
```
mAP(D) = mAP_sat - α * max(0, D* - D)   (阈值模型)
vs
mAP(D) = a * log(D) + b                 (对数模型, 多样性优先)
vs
mAP(D) = const                          (架构上限主导)
```

**模型选择**: 用 AIC/BIC 比较三个模型，若阈值模型 AIC 最低，则 P3.1 成立。

**预期成果**: 量化多样性阈值 D*，修正论文 C10 主张为"最小多样性阈值"。

### 5.4 实验 V5: 双随机性必要性消融

**目标**: 验证 C7——Sinkhorn 双随机性（列归一化）是否真的必要。

**对照**:
| 实验组 | 耦合方式 | 列归一化 | ε | 预期 |
|:------:|:--------:|:--------:|:-:|:----:|
| V5-A | Sinkhorn sample (完整 Sinkhorn) | ✓ (b=1/M) | 5 | 0.750 (baseline) |
| V5-B | **Sinkhorn 输出后移除列归一化** | ✗ (仅保留行归一化) | 5 | ? |
| V5-C | Hard OT | — | 0 | 0.735 |
| V5-D | Random | — | ∞ | 0.751 |

**V5-B 设计的关键修正**:
> 原方案用"温度缩放 sample"（`P_ij = softmax(-C_ij / ε)`）作为 V5-B 的耦合方式。但**行 softmax 与 Sinkhorn 的差异不止"缺少列归一化"**——行 softmax 完全没有迭代更新，初始代价矩阵的结构会原样保留，而 Sinkhorn 的行归一化是在列归一化迭代之后进行的，已经包含了列约束的部分信息。
> 为隔离"列归一化"这一个变量，V5-B 应当**保留 Sinkhorn 的迭代过程，仅在最后一步移除列归一化**：
> ```python
> # V5-B: 仅做行归一化的 Sinkhorn (单步)
> P = exp(-C / epsilon)
> P = P / P.sum(dim=1, keepdim=True)  # 行归一化
> # 不做列归一化迭代
> ```
> 这样 V5-A vs V5-B 的唯一差异就是"是否做列归一化迭代"，符合消融实验的"单变量原则"。

**关键预测**: 若论文 C7 成立，V5-B 应显著低于 V5-A（小染色体监督不足）。**注意**：V5-B 与 V5-A 的差异需达统计显著（多种子 paired t-test，见 §6.3），否则不能宣称 C7 成立。

**配置文件**: `experiments/configs/ldmdet/verify_v5_{A-D}.py`

## 9. 成功标准与判定规则

### 9.1 命题验证的统计标准（基于多种子配对检验）

> **核心原则**: 在 0.001-0.004 mAP 量级做科学论断，**单种子结果不可接受**。所有"证实/推翻"判定必须基于多种子配对检验，否则只能标注"方向一致/未复现"。

| 命题 | 判定标准 | 统计要求 |
|------|----------|----------|
| P1.1 (H(V\|Z)=0 for Hard OT) | `H(V\|Z)_{HardOT} < 0.01` 且 `H(V\|Z)_{Random} ∈ [log(M)-0.1, log(M)+0.1]` | 离线测量，绝对误差 < 0.01（无需多种子） |
| P1.2 (argmax D_eff ε-不变) | `std(D_eff(argmax, ε)) / mean(D_eff(argmax, ε)) < 0.05` 跨 ε ∈ [0.1, 100] | 离线测量，CV < 5%（无需多种子） |
| P1.3 (sample D_eff 单调递增) | Spearman ρ(D_eff(sample, ε), ε) > 0.9 | 离线测量，p < 0.01（无需多种子） |
| **P2.1 (sample > argmax 普适)** | **多种子 paired t-test**: `mean(mAP_sample - mAP_argmax) > 0` 且 `p < 0.05`，95% CI 不包含 0 | **至少 3 种子** |
| P2.2 (三区域, ε≈5 达峰) | `argmax_ε mAP(ε) ∈ [3, 7]` 且两端下降 > 0.005 | 单种子可做趋势观察，**最终判定需多种子** |
| P3.1 (阈值效应) | 阈值模型 AIC < 对数模型 AIC，且 D* 的 95% CI 不包含 0 | ΔAIC > 2，**需多种子拟合混合效应模型** |

**关键修正**:
- **P2.1 的判定**: 原方案"若任一 ε 下 argmax > sample + 0.003 mAP 则推翻"**已废弃**。该规则在单种子下会把 0.003 的噪声差异误判为"推翻"。新规则要求**多种子 paired t-test**，仅当 `mean(Δ) > 0` 且 `p < 0.05` 时才判定方向；若 `p ≥ 0.05`，标注"统计不显著"。
- **P2.2 的判定**: 单种子可做"趋势观察"（如 ε=5 是否在峰值附近），但不能做"达峰"判定。最终判定需多种子验证峰值稳定性。

### 9.2 实验成功的最低要求

- **Phase 1**: 至少完成 V2 离线测量，产出 `diversity_phase_diagram.json`
- **Phase 2**: 至少完成 V1-E, V1-F, V1-G, V1-H 四组关键对照，**每组 3 种子**
- **Phase 3**: 至少完成 V3 的 ε ∈ {0.5, 1, 2, 5, 10} 五组扫描（单种子，用于趋势观察）
- **Phase 4**: 完成 E4.1 vs baseline 的直度对比

### 9.3 多种子规划与配对检验

**为什么需要多种子**:
- CV 训练的 run-to-run 方差通常 0.3-0.8%（0.003-0.008 mAP）
- 论文表 1 的 "sample > argmax" 差距仅 +0.006 mAP
- E4.3 的 "argmax > multinomial" 差距仅 +0.004 mAP
- **单种子下，0.001-0.004 mAP 的差异在噪声内，无法做因果归因**

**多种子规划**:

| 实验组 | 种子数 | 配对方式 | 检验目标 |
|:------:|:------:|:--------:|:--------:|
| V1-E vs V1-F | **3 种子** | 同种子配对 (seed=1..3) | sample vs argmax 在新版 OT ε=5 下的差异 |
| V1-G vs V1-H | **3 种子** | 同种子配对 (seed=1..3) | sample vs argmax 在 legacy OT ε=1 下的差异 |
| V5-A vs V5-B | **3 种子** | 同种子配对 (seed=1..3) | 列归一化的必要性 |
| V6-A vs V6-B | **3 种子** | 同种子配对 (seed=1..3) | 行 vs 列归一化的影响 |

**种子选择**: seed ∈ {1, 2, 3}（固定的 3 个种子，便于复现）。

**配对检验流程**:
1. 对每对 (sample, argmax) 在相同 seed 下训练，得到 (mAP_sample[seed], mAP_argmax[seed])
2. 计算 Δ[seed] = mAP_sample[seed] - mAP_argmax[seed]
3. 对 Δ 序列做 Shapiro-Wilk 正态性检验
4. 若正态: paired t-test；若非正态: Wilcoxon signed-rank test
5. 报告: mean(Δ), std(Δ), 95% CI, p-value, 效应量 (Cohen's d)

**判定规则**:
- `p < 0.05` 且 95% CI 不包含 0 → 方向判定（"sample > argmax" 或 "argmax > sample"）
- `p ≥ 0.05` → "统计不显著，无法判定方向"
- **无论结果如何，都不能用单种子结果做"推翻"判定**

**资源估算**:
- V1-E/F/G/H: 4 组 × 3 种子 = 12 次训练，每次 ~30 小时 → 360 GPU-小时
- V5-A/B, V6-A/B: 4 组 × 3 种子 = 12 次训练 → 360 GPU-小时
- 总计: ~720 GPU-小时（约 30 天单卡，或 4 天 8 卡并行）

### 9.4 D_eff 实测验证（论文 D_eff≈2.80/5.31 的独立复核）

**为什么需要独立复核**:
- 论文图 7 报告 argmax D_eff≈2.80（跨所有 ε）、sample D_eff: 2.81→5.31（ε=0.01→100）
- 这些 D_eff 值是后续所有理论推导的基础（CAM 定理、多样性阈值等）
- **如果 D_eff 值不可复现，整个理论框架的实证基础就动摇了**
- 论文未提供 D_eff 计算的代码或独立验证

**验证流程**:

1. **实现 D_eff 计算**:
   ```python
   # D_eff 定义: 有效匹配数 = (sum s_j)^2 / sum(s_j^2)
   # 其中 s_j = sum_i P_ij 是传输矩阵的列和
   def compute_deff(transport_matrix):
       col_sums = transport_matrix.sum(dim=0)  # [M]
       deff = (col_sums.sum() ** 2) / (col_sums ** 2).sum()
       return deff.item()
   ```

2. **在 SOTA checkpoint 上离线测量**:
   - 对验证集每张图，计算 argmax 和 sample 两种解码下的传输矩阵
   - ε ∈ {0.01, 0.1, 0.5, 1, 2, 3, 5, 10, 50, 100}
   - 报告: mean(D_eff), std(D_eff), 与论文值的相对误差

3. **判定标准**:
   - |measured_D_eff(argmax) - 2.80| / 2.80 < 10% → 论文 argmax D_eff 复现成功
   - |measured_D_eff(sample, ε=0.01) - 2.81| / 2.81 < 10% → 论文 sample 起点复现成功
   - |measured_D_eff(sample, ε=100) - 5.31| / 5.31 < 10% → 论文 sample 终点复现成功
   - Spearman ρ(D_eff(sample, ε), ε) > 0.9 → 单调性成立

4. **若复现失败**:
   - 检查 D_eff 定义差异（是否用归一化后的传输矩阵？）
   - 检查 cost 矩阵定义差异（L2 vs IoU？归一化方式？）
   - 检查 Sinkhorn 迭代次数影响
   - **若复现失败，所有基于 D_eff≈2.80/5.31 的理论推导需重新评估**

**前置性**: D_eff 实测验证应在 Phase 1 完成，**先于 V1-V9 任何训练实验**。若 D_eff 不可复现，后续实验的解读需调整。

## 附录 B: 插桩代码骨架

```python
# projects/LDMDet/mods/coupling_diagnostics.py

import torch
import json
import os
from pathlib import Path

class CouplingDiagnostics:
    """耦合诊断器, 通过配置开关启用."""
    
    def __init__(self, enable=False, log_dir=None, log_every=100,
                 compute_entropy=True, compute_variance=True,
                 compute_deff=True, save_transport=False,
                 group_labels=None):
        self.enable = enable
        self.log_dir = Path(log_dir) if log_dir else None
        self.log_every = log_every
        self.compute_entropy = compute_entropy
        self.compute_variance = compute_variance
        self.compute_deff = compute_deff
        self.save_transport = save_transport
        self.group_labels = group_labels  # 24 类的组标签
        self.buffer = []
        self._step = 0
    
    def record_coupling(self, noise, gt_diffusion, transport, 
                        matched_idx, cost, coupling_mode, epsilon,
                        gt_labels=None):
        """插桩点 B/C: couple() 调用后记录."""
        if not self.enable:
            return
        
        record = {
            'step': self._step,
            'epsilon': epsilon,
            'coupling_mode': coupling_mode,
            'num_proposals': noise.shape[0],
            'num_gt': gt_diffusion.shape[0],
        }
        
        # H(V|Z): 条件速度熵
        if self.compute_entropy and transport is not None:
            # transport: [M, N] 或 [N, M], 统一为 [N, M] (每行一个 proposal)
            if transport.shape[0] != noise.shape[0]:
                transport_norm = transport.t()  # [M,N] -> [N,M]
            else:
                transport_norm = transport
            row_sums = transport_norm.sum(dim=1, keepdim=True).clamp_min(1e-10)
            row_probs = transport_norm / row_sums  # 每行和为 1
            entropy_per_row = -(row_probs * (row_probs + 1e-10).log()).sum(dim=1)
            record['H_V_given_Z'] = entropy_per_row.mean().item()
            record['H_V_given_Z_std'] = entropy_per_row.std().item()
        
        # D_eff: 有效匹配数
        if self.compute_deff and transport is not None:
            # 列和分布
            if transport.shape[0] != noise.shape[0]:
                col_sums = transport.sum(dim=1)  # [M]
            else:
                col_sums = transport.sum(dim=0)  # [M]
            col_sums = col_sums.clamp_min(1e-10)
            d_eff = (col_sums.sum() ** 2) / (col_sums ** 2).sum()
            record['D_eff'] = d_eff.item()
        
        # 在线 D_eff (从 matched_idx 统计)
        if self.compute_deff and matched_idx is not None:
            unique, counts = torch.unique(matched_idx, return_counts=True)
            online_d_eff = (counts.sum() ** 2) / (counts ** 2).sum()
            record['D_eff_online'] = online_d_eff.item()
            record['H_matched_idx'] = -(counts.float() / counts.sum() * 
                                        (counts.float() / counts.sum()).log()).sum().item()
        
        # 传输代价
        if cost is not None and transport is not None:
            if transport.shape[0] != noise.shape[0]:
                # transport [M,N], cost [M,N]
                mean_cost = (transport * cost).sum().item()
            else:
                # transport [N,M], cost [N,M]
                mean_cost = (transport * cost).sum().item()
            record['transport_cost'] = mean_cost
        
        self.buffer.append(record)
        
        if len(self.buffer) >= self.log_every:
            self.flush()
    
    def record_velocity(self, x_start, x_noise, x_noisy, t):
        """插桩点 D/E: 前向扩散后记录速度统计."""
        if not self.enable or not self.compute_variance:
            return
        
        velocity = x_noise - x_start  # [N, 4]
        
        # 总方差
        total_var = velocity.var(dim=0).sum().item()
        
        # 组间/组内方差分解 (需 gt_labels, 此处简化)
        record = {
            'step': self._step,
            'total_var': total_var,
            't': t.mean().item() if t.numel() > 0 else 0.0,
        }
        self.buffer.append(record)
    
    def flush(self):
        """将 buffer 写入磁盘."""
        if not self.log_dir or not self.buffer:
            return
        self.log_dir.mkdir(parents=True, exist_ok=True)
        out_file = self.log_dir / f'coupling_diag_{self._step}.json'
        with open(out_file, 'w') as f:
            json.dump(self.buffer, f, indent=2)
        self.buffer.clear()
    
    def step(self):
        """每个训练 step 调用."""
        self._step += 1
```

## 总结

本方案设计了 **4 层验证体系**:

1. **诊断层验证** (V2, V7): 离线测量 H(V|Z), D_eff, 方差分解，验证 P1.1-P1.4

3. **原则层验证** (V3, V4): ε 扫描 + 阈值拟合，验证 P2.2, P3.1
4. **失败机制分析** (V8, V9): 尺度条件化失效根因 + 架构上限修正

**最小可执行集** (资源受限时):
- Phase 1 全部 (离线测量，无需训练)
- V1-E, V1-F, V1-G, V1-H (4 组关键对照)
- V3 的 ε ∈ {0.5, 1, 2, 5, 10} (5 组扫描)

总计 **5 个工具脚本 + 9 组训练实验**，可在现有 GPU 资源下完成。
